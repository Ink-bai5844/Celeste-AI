# Celeste 辅助机

默认由玩家正常游玩。需要帮助时，在独立小地图窗口点击一个目标格；需要控制路线时，再依次添加多个 8 像素格子、设置分段限制，点击「确认整条路线」。程序从当前实际玩家状态进行后台物理模拟和路线搜索，完整验证所有点能够按顺序连续存活经过后，才接管执行。成功、取消或失败后归还控制。

本仓库发布源码、测试、工具与启动器，不包含 Celeste 游戏本体、地图资源、存档、预先修改的游戏副本或已构建桥接。需要自行合法安装 Celeste，再在本机准备隔离游戏副本。开发环境的 `GAME/`、`.dev/`、`artifacts/`、`handoff/`、运行输出、日志和含凭据的本地配置不随源码发布。

下文 `artifacts/...` 是开发期间的本地诊断记录路径，公开克隆中不存在；保留这些字面路径用于说明验证范围，不是下载链接或运行依赖。各段测试数量、耗时与实机结果属于对应历史版本，不代表新克隆已完成冷安装或所有关卡都已验证。

## 启动

### macOS

首次克隆后先准备以下依赖：

- 自己安装的 macOS Celeste。当前构建流程针对包含 `Celeste.exe`、`FNA.dll` 的 Mono/FNA 应用包，已验证的是 Steam 版本；其他发行版或新版运行环境需另行验证。
- Python 3.10+，且该解释器可以使用 Tkinter。可运行 `python3 -m tkinter` 检查是否正常打开测试窗口，关闭测试窗口后继续；缺少 Tk 时按 Python 发行方说明安装。[Python Tkinter 文档](https://docs.python.org/3/library/tkinter.html)
- .NET SDK，以及能够运行 `net9.0` 工具的 .NET 9 运行时。当前 `BridgeInstaller` 目标和构建脚本路径固定为 `net9.0`，只安装更新版本 SDK 不一定包含所需运行时。微软已将 .NET 9 列为停止支持版本，这是当前构建链尚未迁移的限制；本文不声称已适配更新目标框架。[macOS .NET 安装与版本说明](https://learn.microsoft.com/en-us/dotnet/core/install/macos)

在克隆得到的仓库根目录创建 Python 环境。当前辅助机的 Python 包没有额外运行时依赖；旧 `Celeste-NEAT` 的依赖不是此流程所需。

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e ./Celeste-Search
.venv/bin/python -m tkinter
dotnet --list-sdks
dotnet --list-runtimes
```

确认 Tk 测试窗口能打开，并且 `dotnet` 可用后，关闭测试窗口，首次构建桥接。若 Steam 库在别处，请修改 `--source-app`；`--dotnet` 显式使用本机工具，不依赖未随仓库提供的 `.dev/dotnet`。

```sh
.venv/bin/python tools/build_mac_bridge.py \
  --source-app "$HOME/Library/Application Support/Steam/steamapps/common/Celeste/Celeste.app" \
  --dotnet "$(command -v dotnet)"
```

首次构建需要下载 NuGet 依赖。脚本将原应用复制到 `GAME/Celeste-Mac/Celeste.app`，编译并注入桥接，只修改项目内副本，不覆盖 Steam 原安装。游戏运行时继续使用它自带的 Mono/FNA。构建输出、NuGet 缓存和安装记录在本地生成，不需要从其他开发者的工作目录复制。

构建成功后先打开 Steam，再从 Finder 双击 `start_celeste_assist.command`，或运行：

```sh
chmod +x start_celeste_assist.command
./start_celeste_assist.command
```

默认打开辅助窗口并启动上述项目内游戏副本。进入存档和关卡后，辅助窗口会自动连接。之后未修改桥接源码时可直接使用启动器；若该副本已经运行，只打开辅助窗口：

```sh
./start_celeste_assist.command --no-launch
# 调整后台搜索进程数及每种基础策略的预算
./start_celeste_assist.command --no-launch --workers 6 --plan-seconds 8
```

启动器依次使用 `CELESTE_PYTHON` 指定的解释器、项目 `.venv/bin/python`、已安装的 Python Framework 当前版本，最后使用 PATH 中的 `python3`。修改桥接源码后，先正常退出游戏副本，再重复上面的显式构建命令。只有自行在 `.dev/dotnet/dotnet` 准备好工具、且使用默认 Steam 路径时，才可直接用 `./start_celeste_assist.command --build`；这个选项不会自动安装 SDK。

游戏副本仍使用 macOS 的正常 Celeste 存档目录。每次通过启动器启动前，会将现有 `Saves` 和 `Backups` 按内容校验后备份到本地 `artifacts/mac-save-backups/`；这不是独立存档沙盒，也不包含其他开发者的历史存档备份。

上述首次安装流程已按当前脚本与项目文件核对；尚未在一台无游戏副本、无 SDK、无缓存的新 Mac 上完整实测冷安装。历史本机运行记录见下方「验证」。

### Windows

Windows 入口保留，使用 Python 3.10+、Tkinter、`dotnet` 构建工具及项目要求的 XNA 程序集。先自行准备合法游戏的隔离 XNA 副本，并配置桥接入口；`start_celeste_assist.ps1` 只编译和部署 DLL，不会自动向全新 `Celeste.exe` 注入入口。入口配置可参考 [Instrumentation 安装说明](Celeste-Instrumentation/README.md#installation)，其中旧版预编译发布包并非本仓库附带文件。准备好副本后，在项目目录运行：

```powershell
.\start_celeste_assist.ps1 -LaunchGame
```

使用其他游戏副本：

```powershell
.\start_celeste_assist.ps1 -GameDir .\GAME\Celeste-2 -LaunchGame
```

游戏已运行时，请先正常退出该副本，再用辅助机启动，以载入新的桥接；编译新 DLL 不会更新已经载入的旧 DLL。省略 `-LaunchGame` 只打开辅助窗口，可以使用窗口里的启动游戏按钮。兼容入口 `start_celeste_search.ps1` 也启动辅助机。此次公开源码整理未重新验证 Windows 冷安装。

## 使用

1. 正常进入自己的存档和关卡，等待辅助窗口显示连接成功。
2. 小地图左键依次添加路线点，地图和右侧列表显示编号。房间下拉框可选择同一章节其他房间；切换房间不会清除已选路线。滚轮缩放，中键拖动，「定位玩家」返回玩家所在房间。
3. 在右侧列表选中一个点，可设置进入该点这一段的「禁止冲刺」「禁止落地」；第 1 段从当前玩家位置出发。可以删除、清空、上移或下移；限制跟随终点移动，调整顺序后应核对。最多 32 个点。
4. 点击「确认整条路线」。选点和编辑草稿不会接管，也不会修改已经提交的路线。搜索期间游戏持续运行，辅助机会等待可稳定复现的起点；搜索、执行和自动重试期间按游戏操作键都会取消本次辅助。
5. 执行时连续经过所有点，中途不松键等待下一段搜索。全部到达后自动归还控制；轨迹偏移会记录警告并继续当前完整动作。死亡、分段限制被违反或动作执行完仍未到达时，等待自然复活或落稳，再在预算内自动尝试其他完整候选；不会把不同生命中经过的点拼接成成功。人工操作、取消和断连仍立即释放控制。

「禁止冲刺」同时排除冲刺输入、已缓存冲刺和上一段尚未结束的冲刺。「禁止落地」允许从地面起跳，但离地后直到到达该段终点都不能再次接触地面，也不能沿地面走到终点；终点若必须落地，就不能为该段勾选此项。

默认偏好少用、晚用冲刺：有序搜索先用一小段预算尝试无冲刺分支，再保留冲刺余量不同的到达状态继续搜索；后段走不通时，可以回退到前面的节点重新选择冲刺时机。并行候选优先比较实际冲刺次数，再比较冲刺发生时的移动进度，最后比较路线长度。带冲刺的首个完整候选会保留至多 1 秒供其他策略比较；没有更好的结果仍可执行该完整候选。这个偏好不改变任何分段禁令，也不保证有限预算内找到全局最少冲刺路线。

地图能通向相邻房间的边界会向外延伸青色箭头。新点击出口时，会选择同一边界、同一邻房的整段连续可通过开口，任意有效格真正切图均算到达；列表显示「出口 N 格均可」，地图描出这段范围。永久墙体隔断或通向不同房间的开口不会合并，部分可通行格按真实通道裁窄。已有保存路线保持原单格语义，重新点击出口才会扩展。可破坏墙、移动机关和危险物仍由物理搜索检查，箭头不保证当前状态一定可达。

新增「区域起跳与精确收尾」策略：从实际玩家状态走动或跳跃，保留连续平地两端、不同起跳位置和速度的真实到达状态；这些前缀动作会完整保留。普通终点附近的连续平地可以先作为内部落脚区域，再用步行或跳跃进入原来准确选中的格子；落在附近本身不算成功。移动支撑使用当前机关状态与实体身份，消失的支撑不会保留为落脚点。禁止冲刺、禁止落地和路线顺序在前缀、中转、收尾的每一帧继续生效。

区域搜索先保留不用冲刺的连接，也为需要冲刺的备选留出预算；后段失败可继续尝试前段其他实际到达状态。全状态保留速度、体力、冲刺、输入边沿和机关时间，不会制造一个「已在平台另一端」的起点。它与原有机关、多通路等策略并行竞争，仍受节点、时间、路线帧数与候选数上限约束，不保证穷尽所有像素起跳方式或找到全局最优解。

搜索没有到达终点时，途中真实到达的其他平地也会保留为继续点，包括偏离终点方向的分支，以及先落地、随后才失败的分支。每块已发现的支撑面分别保留实际到达状态，轮流向后搜索；不会因为另一块平台更靠近终点就把整块平台丢掉。同一平台上的不同速度、体力或机关状态也会轮流获得续搜机会。继续点携带从原起点出发的完整动作、机关时间和路线阶段，可连续串起多块平台；附近落地仍不算完成公共目标。同一平台最多保留 12 个待搜索或暂停的状态代表，重复状态只保留更省冲刺或更短的前缀，搜索继续受总时间、节点和动作帧数预算限制。

区域起终点的前一轮验证记录见区域起终点验证（本地记录 `artifacts/regional-endpoints-upgrade/verification.md`）。本轮继续点升级完成 995 项测试（990 通过、5 跳过）；在相同 2400 次展开预算下，先向左绕行再连续向右换台的场景由失败变为成功，最终路线 219 帧、零冲刺。搜索覆盖面扩大也会增加简单场景的搜索开销；这不保证所有关卡都更快。完整验证范围及离线、实机验证边界见平地继续搜索验证（本地记录 `artifacts/ground-frontier-upgrade/verification.md`）。

搜索采用并行策略池，包含不同动作粒度、攀墙换台、登高恢复、补充冲刺、多级平台中转、下绕和移动平台接力等方法。攀墙策略把实际抓墙状态作为内部中转目标，尝试连续起跳、斜上冲刺、抓墙上爬和反跳落台，保留暂时远离终点但能在高处恢复冲刺的路线。默认使用逻辑处理器数量的一半，最多 12 个后台进程；在 Windows 上以低于正常的优先级计算。辅助机在连接游戏前预热全部进程，避免首次搜索的进程启动拖慢游戏回包。不同策略同时竞争，失败的空位立即交给下一种策略；只有完整有效路线通过起点核对后才能执行。小地图显示当前并行数、已完成数量和策略名称。可用 `-Workers 6 -PlanSeconds 8` 调整进程数和每种基础策略的预算，复杂中转策略会分配更多时间。

勾选「搜索候选」可实时查看各后台进程的主要候选路线。每个 W 编号有固定颜色，实线表示主候选，虚线表示备选；标注「局部」的轨迹只是正在探索的内部片段。旁边的下拉框可以只看某个进程，悬停进度文字可查看策略和扩展数量。轨迹约每 0.4 秒更新，跨房间部分分开绘制；取消或更换目标会清除旧轨迹。预览不参与接管判定，只有整条路线通过验证后才执行。

单目标、当前房间出口和多个公共路线点均支持「多通路轮换验证」：先按玩家身形、实心地形、尖刺和单向平台方向生成不同的绕行通道，以及落脚、攀墙、补充冲刺的资源链。该策略优先进入工作进程，先给不同通路一次短探测，再轮流继续搜索，保留各自的搜索进度。一条通路内部优先沿已到达状态向后推进，走不通再回溯；每次短探测后仍会换其他通路，不需要把整条测完。多点路线只按真正完成的公共路线点给予进度优先，同阶段保持轮换；单终点任务还参考真正到达的内部中转点进度，同时定期轮换其余候选。抓墙等准备动作成功后，会先尝试它所准备的平台目标，避免在同一目标两侧反复抓墙；失败仍回溯其他真实到达状态，推进到下一目标后重新允许准备动作。内部落脚点只用于引导，不替换用户选定的格子或出口；每一段保留真实速度、冲刺、体力及机关状态。几何候选不保证物理可达；只有原始公共目标、分段限制和完整动作重放全部通过，才允许接管。原有全局顺序搜索继续作为独立策略竞争。

通路候选按每页 6 条继续发现，每个阶段最多保留 24 条，兼顾不同绕行方向、出口位置及机关组合。碰撞网格和几何搜索队列也支持续算，暂时超时不能当作「后面没有通路」。普通物理搜索每片最多 64 次展开，并以 0.2 秒为切片目标；攀墙、补充冲刺等复杂动作保存配方游标及执行中状态，换回来继续计算，相同完整物理状态下的重复前段会共享计算结果。已计算动作的最终认证及最后一个已计费配方的收尾可能超过切片时限。小地图区分「尚未尝试」「等待下一轮」「验证中」并显示已尝试数量和轮次；灰色虚线是几何候选，彩色物理轨迹采用采样显示，未画出彩线不代表没有尝试。候选数、总时间、总节点及动作帧数仍有限，预算用完不等于证明所有通路不可达。验证记录见多通路轮换与覆盖验证（本地记录 `artifacts/route-round-robin-upgrade/verification.md`）。准备动作循环的通用修复与当前两点路线验证见连续目标寻路验证（本地记录 `artifacts/general-reachability-upgrade/verification.md`）。

补充冲刺的绿晶可组成有界连续资源链。通路排序考虑当前绿晶冷却、没有补给的一段需要上升多高、连续飞行距离，以及真实落脚后起跳的机会；会保留不同绕行方向，不把最短几何距离等同于最容易完成。接触补给必须验证对应实体的实际拾取，保留不同高度、速度和冲刺状态。下降到补给时可先尝试直接接触，抓墙作为备选；接近平台却无法直接落上去时，会先尝试实际抓住附近侧壁，再爬到原平台。所有这些中间动作都经过原分段限制和物理重放。

多点路线需要补给中转时，「自动补充与折返」策略会尽早进入并行池，并在同一顺序搜索中加入连续跳冲接补给的实际动作。远处绿晶允许先沿现有平台助跑再起跳，助跑期间仍检查平台边缘、尖刺和跳跃宽限时间；不会直接挪动起点。补给后保留多个真实速度与冷却状态，返程可先抓墙调整高度、等待恢复，再接下一颗补给。多通路和区域搜索也为前段其他到达方式保留轮次，避免首个到达状态的困难后缀耗尽全部机会。这些改进不改变公共路线点、分段限制或物理参数。

连续机关路线使用独立的有界接力搜索：将弹簧、移动块两侧的实际抓点、不同乘坐时机、补给和落脚平台组合成候选链。每次接触都保留真实速度、惯性、体力、冲刺及全部机关阶段，先尝试不用冲刺的动作，再放宽搜索；后续失败会继续其他到达状态。已接上的分支优先向后探索，不必先穷举前一个机关的所有相似动作；真实落脚恢复资源后，可接续多通路平台搜索。机会图只用于排序，不能把预估终点位置当作已经到达，仍需原目标顺序、分段限制和整条物理重放全部通过。生产逻辑不指定房间名、路线坐标或固定按键录制。

局部搜索按扩展次数分配预算，后续路段共享该通路剩余时间，同时为其他通路保留探索机会并服从全局截止时间。相邻的同朝向静态墙抓点会先用小预算比较实际到达候选，再深入后段，避免低墙死路耗尽预算后才尝试高墙；落脚、补充资源和机关条件仍按顺序验证。冲刺次数按模拟器实际开始冲刺的事件统计，包含缓存输入及同帧补充后的冲刺；偏好少用、晚用，但不保证全局最少。

单点目标也会自动搜索内部中转路径，无需玩家手工标出每个平台。多点和带限制的路线使用保留全局点位顺序的搜索策略；全部策略能同时运行时，会连续使用本次剩余预算，避免频繁切换短任务。相同完整起点、路线和策略可以在同一进程内继续尚未搜完的分支，缓存有容量限制。取消、更换目标或实际起点变化时，旧计算会快速退出，避免挤占新任务。失败会显示原因；搜索预算耗尽只表示本次未找到路线，不代表数学上不可达。整条路线从同一个起点连续模拟，保留经过每个点时的速度、冲刺余量和机关状态；不会拼接各自重置状态的独立片段。

不带分段限制的多点路线还会尝试移动平台接力，保留乘坐途中不同高度的起跳选择；即使继续乘到终点会撞上天花板，较早的安全起跳状态仍参与搜索。往返过程使用平台当时的位置和运动阶段，返回路线失败后仍可尝试其他到达前一个点的状态。

移动平台接力会在登台和乘台后尝试直接前往当前路线点，包括沿平台冲刺、在边缘借上升速度起跳、反向对齐窄通道再向上冲刺。动作时机由平台边界、目标列和实际模拟状态决定；多个到达状态仍交给同一个顺序搜索继续验证后续点。

当平台顶部被尖刺完全覆盖时，搜索会尝试抓住两侧并随平台移动，在途中或终点释放、跳出，再继续前往路线点。部分带刺的平台仍保留安全位置的登台分支。侧面搭乘全程模拟体力、接触、尖刺和移动状态，不会把抓到平台本身视为完成用户路线。

移动平台也参与条件通路搜索：候选需要实际触发平台、等待本体和附属尖刺让开，再从安全区域穿过。平台载人越过开口时，允许在不同安全高度继续，不要求回头踩中一个几何中间点。搜索保留出程、回程及回程爬升的离开机会，也保留背离目标的临时抓墙；动态平台转接和松手绕过下沿的动作按小时间片续跑，与其他通路轮换。所有方案仍须从原起点完整重放到原目标，才会交给游戏执行。

点击「取消」，在辅助窗口按 Esc，或在游戏中按操作键，均可结束接管。游戏内 F12 断开辅助；点击辅助窗口右上角「重新连接」即可恢复，无需切回游戏按键。按钮显示「正在连接…」时等待真实握手，超时或失败后可以重试。首次更新这一功能需要正常重启辅助版游戏以加载新版桥接，之后每次重连不需重启。F11 仍是旧快捷键入口，但可能与系统窗口快捷键冲突，日常可直接使用「重新连接」按钮。关闭辅助窗口会释放控制，游戏继续运行。

## 行为与限制

- 默认不自动搜草莓、不自动通关；只执行玩家确认的整条路线。
- 搜索和候选路线验证在后台进程计算，不用真实游戏批量试跑，不暂停游戏。
- 不强制重开章节或房间。死亡使当前候选失败；等待游戏自然复活后，保留原整条路线重新搜索，点位进度清零，不把不同生命中经过的点拼成一次成功。
- 预测轨迹或机关状态偏离会记录警告，继续尝试当前完整动作。实际死亡、动作结束后仍未完成或实际违反分段限制时，记住失败动作指纹，并自动搜索其他候选；人工操作、取消及断连仍立即释放控制。
- 保留路线中的跨房间动作与切版跳；不会把部分路线或邻近位置当成目标已达成。
- 人工操作取消整个辅助请求；死亡、场景变化和起点失配会淘汰旧搜索结果，接管前再次检查实际状态。
- 默认每轮搜索预算 120 秒、最多 8 轮，最多 8 次实际执行失败；复杂通路、区域及机关策略单次最多 90 秒，节点预算保持有限。执行预算至少 30 秒，较长路线会按预计时长和切版次数增加余量。自然复活或落稳最多等待 30 秒。所有候选仍先验证完整路线，预算耗尽只表示本轮未找到更多路线，不代表数学上不可达。
- 物理模型尚未覆盖所有章节机关。无法稳定复现状态或不支持的游戏时步会拒绝接管并提示原因。
- 掉落方块必须有完整、新鲜且可解析的原生状态；`behind`、Boss 变体和持久外部触发标记 `Triggered=true` 暂不支持，拒绝接管。普通抓附触发不等同于该外部标记；缺失数据也不会被猜成闲置状态。
- 当前磁带支持已验证 11z 的节拍方块、攀升路线及拾取后的静态房间与出口；拾取剧情本身、带附属尖刺等特殊组合，以及无法取得新房间节拍的活动磁带跨房续算仍不支持。尚未拾取时，如果目标格必然触发拾取，会立即指出对应路线点并保持手动控制；邻近但仍有安全位置的目标格继续参与正常搜索。已确认停止状态的当前房间内，原磁带位置恢复为普通目标。
